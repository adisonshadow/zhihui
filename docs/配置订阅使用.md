# 配置订阅使用

本文档说明如何在应用内使用**配置订阅模式**：配置面板可在任意界面以 Modal 形式打开，配置修改后根据订阅记录通知被订阅方。

## 1. 核心概念

- **配置面板**：AI 模型配置等全局设置，以 Modal 形式打开，可从任意界面（项目列表、项目编辑、设计器等）唤起。
- **订阅**：业务模块通过 `useConfigSubscribe` 订阅配置变化；配置保存成功后，所有订阅者会收到最新配置并重新渲染。
- **数据流**：主进程持久化 → 渲染进程获取 → 订阅者持有最新副本；保存时写回主进程 → 主进程确认 → 通知所有订阅者更新。

## 2. 打开配置面板

在任何组件中调用：

```tsx
import { useConfigModal } from '@/contexts/ConfigContext';

function MyComponent() {
  const { openConfigModal } = useConfigModal();

  return (
    <Button onClick={() => openConfigModal()}>
      打开设置
    </Button>
  );
}
```

配置面板会以 Modal 形式覆盖在当前页面上，用户关闭 Modal 后留在当前界面。

## 3. 订阅配置变化

需要消费 AI 配置的模块（如剧情大纲剧本专家、角色设计绘画、视频设计器 AI Chat 等）应订阅配置，以便在用户修改配置后自动使用最新值：

```tsx
import { useConfigSubscribe } from '@/contexts/ConfigContext';

function ScriptExpertChat() {
  const config = useConfigSubscribe();

  if (!config) return <Text type="secondary">加载配置中…</Text>;

  // 按能力筛选：如需要「生成剧本」能力的模型
  const scriptModels = config.models.filter((m) =>
    m.capabilityKeys.includes('script')
  );

  if (scriptModels.length === 0) {
    return (
      <Text type="secondary">
        请在「设置」中配置具备「生成剧本」能力的模型。
      </Text>
    );
  }

  // 使用 scriptModels[0] 或让用户选择
  const apiUrl = scriptModels[0].apiUrl;
  const apiKey = scriptModels[0].apiKey;
  // ...
}
```

## 4. API 说明

### `useConfigModal()`

返回 `{ openConfigModal: () => void }`，用于打开配置 Modal。

### `useConfigSubscribe()`

订阅配置变化，返回当前最新配置 `AISettings | null`。配置加载中为 `null`，加载完成或更新后为 `AISettings`。配置保存成功后，所有调用 `useConfigSubscribe` 的组件都会收到最新 `AISettings` 并重新渲染。

### `useConfig()`（可选）

若仅需读取当前配置、不强制跟随更新，可使用 `useConfig()`。推荐需要「配置变化后立即生效」的分镜使用 `useConfigSubscribe`。

## 5. 能力 tag 与模型筛选

调用 AI 时，按所需能力筛选模型：

| 能力 key        | 说明           | 典型使用分镜           |

| action_script   | 生成动作脚本   | 角色动作               |
| voice_over      | 生成配音       | TTS 对白               |

const modelsForDraw = config.models.filter((m) =>

### 5.1 `presetKey` 与 `isLocal` 字段

`AIModelConfig` 追加两个可选字段（见功能文档 3.1.2）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `presetKey` | `string?` | 由设置面板「常见模型」一键添加时写入，如 `doubao_seedream`；用于 UI 去重与预设更新迁移。无值视为自定义模型 |
| `isLocal` | `boolean?` | 本地部署标记；`true` 时订阅者应跳过 `Authorization` 头，`apiKey` 允许为空字符串 |

订阅者按需过滤：

```ts
const config = useConfigSubscribe();

// 仅云端 voice_over 模型（如计费分镜希望排除本地部署）
const cloudVoiceOver = config?.models.filter(
  (m) => m.capabilityKeys.includes('voice_over') && !m.isLocal
) ?? [];

// 通用写法：构造请求头时按 isLocal 判断
function buildHeaders(m: AIModelConfig): Record<string, string> {
  const headers: Record<string, string> = { 'Content-Type': 'application/json' };
  if (!m.isLocal && m.apiKey) {
    headers.Authorization = `Bearer ${m.apiKey}`;
  }
  return headers;
}

// 查找用户已添加的某预设
const seedream = config?.models.find((m) => m.presetKey === 'doubao_seedream');
```

## 6. 抠图（matting）双通道

`matting` 能力存在两种并存通道（见功能文档 3.1.5）：

- **通道 A**：`AISettings.aiMattingConfigs`（火山引擎 AccessKey/Secret，见 `docs/AI抠图配置说明.md`）；
- **通道 B**：`AISettings.models` 中 `capabilityKeys` 含 `matting` 的条目（如 Qwen-Image-Edit 预设）。

业务侧推荐选择策略：

```ts
function pickMattingSource(cfg: AISettings) {
  const enabledA = (cfg.aiMattingConfigs ?? []).find((c) => c.enabled !== false);
  if (enabledA) return { kind: 'matting_config' as const, config: enabledA };
  const modelB = (cfg.models ?? []).find((m) => m.capabilityKeys.includes('matting'));
  if (modelB) return { kind: 'model' as const, model: modelB };
  return null;
}
```

## 7. TTS（生成配音）与小米 MiMo

- 剧本对白、时间线中的「TTS 配音」只使用 `capabilityKeys` 含 **`voice_over`** 的模型条目；不会在应用内嵌模型文件。
- **本地**：在设置中新增自定义模型并勾选「本地部署」，`apiUrl` 指向本机或局域网内兼容 **OpenAI `audio/speech`** 的服务根地址（通常以 `/v1` 结尾）；勾选「生成配音」能力，按需填写 `model`；密钥字段在本地部署下会自动隐藏。
- **小米 MiMo（云端）**：在设置「常见模型」中选择「小米 MiMo TTS」（`https://api.xiaomimimo.com/v1`、`mimo-v2-tts`、仅「生成配音」），补全控制台 **API Key** 后保存即可。官方说明：[小米 MiMo 开放平台 - 首次调用](https://platform.xiaomimimo.com/#/docs/quick-start/first-api-call)；语音合成能力见平台文档 *speech-synthesis*。
- 旧数据若 `engineId` 为 `local_moss`，打开 TTS 面板时会自动选用当前第一个 `voice_over` 模型，保存后即写入新 id。
